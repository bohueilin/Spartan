# Full-codebase audit + enhancement round (2026-08-25)

Baseline commit `0b4a0fb` (end of the three design-review rounds, plans 001–019).

## How this round was run

A six-lens read-only audit (correctness, UX state coverage, accessibility residuals, i18n/strings,
health-safety + privacy, tests/parity) followed by an adversarial verification pass in which a
second agent tried to *refute* every finding against the current tree. 44 agents total.

**38 raw findings → 31 confirmed → 7 refuted and dropped.** Severity of the confirmed set:
1 blocker, 13 major, 14 minor, 3 nit.

Two further defects were found outside the audit and are included below: one by reading the
scheduling code (silent "Find a time"), one by **looking at the app on a real device** (the
onboarding tagline was invisible in dark mode — no static lens caught it).

## Enhancements shipped (3)

1. **Action feedback with Undo** — the app had no undo and no confirmation anywhere. Snooze, skip
   and reschedule now confirm in a snackbar, and the reversible ones carry **Undo** that restores
   the exact prior state (status, snooze stamp, scheduled minute) and disarms any reminder armed by
   the undone action. Implemented as a one-shot `Channel` event, not UI state, so a snackbar never
   replays on rotation or tab switch.
2. **Post-value reminders offer** (roadmap R2 #1) — the notification permission was previously only
   reachable from Reminder settings. Today now offers reminders *after* a plan is on screen, once,
   and never again once answered either way. The system dialog is only ever launched from an
   explicit tap, so the one-shot prompt is not spent at launch.
3. **End-of-day reflection** (roadmap R2 #2) — an optional evening sheet (Tough / Okay / Strong plus
   an optional note), offered at most once a day after 18:00 and only when there was a plan.
   Persisted in a new `daily_reflections` table (DB v7→v8, additive), included in delete-all, and
   never a notification. Three neutral moods, no score, no grading.

### Toolchain note

Instrumented tests could not run at all on this device until `androidx.test.espresso:espresso-core`
was raised to 3.7.0 — earlier Espresso reflects on `InputManager.getInstance()`, which no longer
exists on API 36+, so every Compose UI test died in `Espresso.onIdle()`. `androidx.test` runner/junit
were raised to match. Compose UI tests also require the screen to be **on**; a dozing device
produces "No compose hierarchies found in the app", which is an environment failure, not a defect.
